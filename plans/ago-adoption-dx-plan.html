Outcome

A Go repository can pin ago with the Go module and state its rule policy in .ago.yml. Coding agents and CI run the same stable command. The published module has visible package documentation, recognized licenses, accurate integration claims, and one optional reusable skill.

Progress

The ledger supplies progress.

Architecture

Scope

Owns: pull request 2 review closure, license layout, package publication, release version, README, and Go-native adoption guidance. It also owns downstream agent instructions and an optional skill in agentstation/skills.

Does not own: new lint rules, a hosted documentation site, editor extensions, a new GitHub Action, or changes to the Go command.

Non-goals: make third-party checks run implicitly inside stock go test or go vet. Do not bypass branch protection. Do not write llms.txt without a documentation website for agents.

Invariants

  1. The primary install is version-pinned in the adopting repository.
  2. Humans, coding agents, local checks, and CI run the same command and policy.
  3. The command does not edit existing agent instructions or CI without explicit input.
  4. Machine output and exit codes remain stable contracts.
  5. Every license file that pkg.go.dev scans contains a recognized license.

Decisions

D1, 2026-08-24: make go get -tool and go tool ago the primary path. Go supports module tool dependencies since 1.24. ago requires Go 1.25.

D2, 2026-08-24: use AGENTS.md for the required command. Keep the reusable skill optional and publish it from agentstation/skills.

D3, 2026-08-24: do not add llms.txt. Its contract maps a website. Repository agents already discover AGENTS.md, skills, Go package docs, and command JSON.
